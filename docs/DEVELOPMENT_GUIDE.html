2. Telemetry & ECS Schema Specification

Vigil normalizes all events into the Elastic Common Schema (ECS), extending it with banking fields (bank.*).

Standard ECS Fields Used:

  • @timestamp: ISO 8601 event timestamp
  • event.category: network, authentication, process, financial
  • event.type: start, access, denied, transaction
  • source.ip, destination.ip, source.port, destination.port
  • user.name, user.roles, user.domain
  • host.name, host.ip, host.os.name
  • threat.tactic.name, threat.technique.id (MITRE ATT&CK)

    • Custom Banking Extensions (bank.*):

    json
    {
  "bank": {

    3. ES|QL Query Catalogue for SOC Investigation

    Vigil leverages ES|QL (Elasticsearch Query Language) to retrieve grounded forensic evidence across millions of events in milliseconds.

    Query 1: Extract Privileged Escalation & Suspicious Logins

    esql
    FROM logs-auth-*
| WHERE event.outcome == "success" AND user.roles == "SUPER_ADMIN"
| STATS count() by user.name, source.ip, destination.ip
| SORT count() desc
| LIMIT 20

    Query 2: Correlate IP Blast Radius across NetBanking & UPI

    esql
    FROM logs-*
| WHERE source.ip == "198.51.100.44"
| KEEP @timestamp, event.category, user.name, bank.upi_vpa, bank.amount_inr, http.response.status_code
| SORT @timestamp asc
| LIMIT 100

    Query 3: Compute ₹ Financial Exposure by Customer Tier

    esql
    FROM logs-banking-*
| WHERE event.type == "transaction" AND bank.batch_id == "BATCH-20260902-8821"
| STATS 
    total_amount = sum(bank.amount_inr),
    tx_count = count(),
    avg_aml_risk = avg(bank.aml_risk_score)
  BY bank.customer_tier

    4. The 6-Step Agentic Workflow Specification

    mermaid
    graph TD
    Trigger["Attack Discovery Alert Trigger"] --> S1["Step 1: Incident Classification & Materiality Check"]
    S1 --> S2["Step 2: Grounded Evidence Retrieval (ES|QL)"]
    S2 --> S3["Step 3: ₹ Business Exposure Lookup (bank.exposure.lookup)"]
    S3 --> S4["Step 4: Containment Action Drafting + HITL Gate"]
    S4 --> S5["Step 5: CERT-In Annexure-1 Report Draft (certin.report.draft)"]
    S5 --> S6["Step 6: Cryptographic Evidence Sealing (evidence.ledger.append)"]

    Step 1: Materiality & Regulatory Classification

  • Input: Attack Discovery Narrative object (narrative_id, threat_category, affected_entities).
  • Logic: Evaluates against RBI Cyber Security Framework & CERT-In 2022 Guidelines:

    • - Direct financial risk $> ₹5,00,000$ (Material).

    - Outage of critical payment system (UPI/IMPS/RTGS) $> 15$ minutes (Material).

    - Customer PII/KYC data exfiltration $> 100$ records (Material).

  • Output: is_material: true, regulatory_clock_limit_hours: 6, mitre_tactics: ["Initial Access", "Privilege Escalation"].

    • Step 2: Grounded Evidence Retrieval via ES|QL

  • Input: Indicators of Compromise (IoCs) from Step 1 (source.ip, user.name, batch_id).
  • Tool: generate_esql executes targeted piped queries against Elasticsearch.
  • Output: Forensic timeline table with query signatures and exact document counts.

    • Step 3: ₹ Business Risk Scoring (bank.exposure.lookup)

  • Input: Compromised accounts and transaction batch IDs.
  • Logic: Queries Core Banking CRM:

    • - Total funds exposed in active batch.

    - Number of HNI vs Corporate vs Retail customers affected.

    - AML risk rating and velocity anomaly score.

  • Output:

    • ```json

    {

    "direct_exposure_inr": 18240000.00,

    "blast_radius_accounts": 18,

    "hni_count": 14,

    "corporate_count": 4,

    "rbi_penalty_exposure_inr": 10000000.00,

    "risk_level": "CRITICAL"

    }

    ```

    Step 4: Containment Action & Human-in-the-Loop Gate

  • Input: Identified root-cause entities (rogue API token, compromised IP, malicious VPA).
  • Proposed Actions:

    • 1. Revoke API Gateway OAuth2 Bearer Token #8821.

    2. Null-route malicious external IP 198.51.100.44 on Palo Alto Firewall.

    3. Freeze pending payout batch BATCH-20260902-8821 in NPCI UPI Switch.

  • Interaction: Renders an interactive approval dialog in the SOC Cockpit.
  • Output: Analyst digital approval timestamp, analyst ID, and execution status.

    • Step 5: Official CERT-In Report Generation (certin.report.draft)

  • Format: Conforms to CERT-In Incident Reporting Form (Annexure 1):

    • - 1. Name of Organisation / Bank

    - 2. Contact Details of CISO / Nodal Officer

    - 3. Date & Time of Incident Detection (Timestamp of Alert Zero)

    - 4. Affected Systems & IP Addresses

    - 5. Nature & Description of Incident (MITRE ATT&CK breakdown)

    - 6. Chronology of Events (ES|QL query-backed timeline)

    - 7. Rupee Loss / Financial Exposure

    - 8. Containment Measures Taken (Action signed by analyst)

  • Sarvam AI Integration: Translates Executive Summary into selected Indic language.
  • Output: Markdown and PDF artifacts.

    • Step 6: Cryptographic Evidence Ledger (evidence.ledger.append)

  • Structure:

    • ```json

    {

    "block_height": 104,

    "timestamp": "2026-09-02T19:28:44.120Z",

    "incident_id": "INC-2026-0902-01",

    "step_name": "CONTAINMENT_APPROVED",

    "data_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",

    "previous_hash": "a591a6d40bf420404a011733cfb7b190d62c65bf0bcda32b57b277d9ad9f146e",

    "current_hash": "7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069",

    "kms_signature": "arn:aws:kms:ap-south-1:123456789:key/vigil-ledger-sign"

    }

    ```

  • Verification API: /api/ledger/verify validates the entire hash chain from Block 0 to N.

    • 5. Mock / Dual-Mode Engine Architecture

    To ensure zero dependencies during team development and rock-solid demo performance:

  • When USE_LIVE_ELASTIC=false or keys are missing:

    • - Uses high-fidelity in-memory SQLite / Python ES|QL parser loaded with the 30-day banking corpus.

  • When USE_LIVE_BEDROCK=false:

    • - Uses the built-in deterministic reasoning engine that generates authentic regulatory narratives.

  • When USE_LIVE_SARVAM=false:

    • - Uses pre-translated multi-lingual dictionary matrix covering Hindi, Tamil, Telugu, Marathi, and Kannada.

  • Switching to Live Production: Simply update .env with credentials; no code changes required.
